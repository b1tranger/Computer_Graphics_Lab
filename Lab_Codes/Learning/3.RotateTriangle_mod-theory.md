## 1. Overview
In modern OpenGL (Core Profile 3.3+), rendering multiple geometry instances with distinct colors can be accomplished in multiple ways. In this module, **Approach 2 (Uniform Variable)** is implemented to render two distinct triangles using a single shader program, a single VAO/VBO pair, and dynamic CPU-to-GPU uniform color passing.

---

## 2. Uniforms vs. Vertex Attributes

| Characteristic | Vertex Attributes (`in vec3 aColor`) | Uniforms (`uniform vec4 ourColor`) |
| :--- | :--- | :--- |
| **Frequency of Change** | Per-vertex (can interpolate smoothly across triangle faces) | Per-draw call / global across all vertices/fragments until changed |
| **Storage Location** | VBO in GPU video memory alongside positions | GPU Program constant registers |
| **Memory Overhead** | Requires additional buffer bytes ($3 \times 4 = 12$ bytes per vertex) | Zero extra buffer bytes |
| **Best Use Case** | Smooth gradients, complex colored models, textures | Solid colors per object, transformation matrices ($M, V, P$), lighting properties |

## 3. Shader Architecture

### Vertex Shader
The vertex shader is strictly responsible for forwarding 3D vertex positions to clip space:

```glsl
#version 330 core
layout (location = 0) in vec3 aPos;

void main()
{
    gl_Position = vec4(aPos, 1.0);
}
```

### Fragment Shader with Uniform
The fragment shader defines `uniform vec4 ourColor`. Because uniforms are global to the program, every fragment generated between `glDrawArrays` invocations inherits the current uniform value:

```glsl
#version 330 core
out vec4 FragColor;
uniform vec4 ourColor;

void main()
{
    FragColor = ourColor;
}
```

## 4. Vertex Data Layout & Offsets
The vertex buffer contains $6$ vertices ($18$ float values total) representing two distinct triangles:

```cpp
float vertices[] = {
    // First Triangle (Vertices 0, 1, 2)
     0.0f,  -0.5f, 0.0f,
     0.9f,  -0.5f, 0.0f,
     0.45f,  0.5f, 0.0f,

    // Second Triangle (Vertices 3, 4, 5)
    -0.45f,  0.7f, 0.0f,
     0.45f,  0.7f, 0.0f,
     0.0f,  -0.3f, 0.0f
};
```

Vertex attribute pointer registration:
```cpp
glVertexAttribPointer(0, 3, GL_FLOAT, GL_FALSE, 3 * sizeof(float), (void*)0);
glEnableVertexAttribArray(0);
```
- **Location `0`**: Maps to `layout (location = 0)`.
- **Size `3`**: 3 floats ($x, y, z$) per vertex.
- **Stride `3 * sizeof(float)`**: Distance from one vertex to the next.
- **Offset `(void*)0`**: Data starts at index 0 of the VBO.

## 5. Draw Calls & Buffer Partitioning
Instead of drawing all 6 vertices in one shot, the render loop invokes `glDrawArrays` twice:

```cpp
glUseProgram(shaderProgram);
glBindVertexArray(VAO);

int vertexColorLocation = glGetUniformLocation(shaderProgram, "ourColor");

// 1. Draw First Triangle (Red)
glUniform4f(vertexColorLocation, 1.0f, 0.0f, 0.0f, 1.0f);
glDrawArrays(GL_TRIANGLES, 0, 3); // starting at index 0, draw 3 vertices

// 2. Draw Second Triangle (Green)
glUniform4f(vertexColorLocation, 0.0f, 1.0f, 0.0f, 1.0f);
glDrawArrays(GL_TRIANGLES, 3, 3); // starting at index 3, draw 3 vertices
```

### Draw Call Parameter Mechanics:
- `glDrawArrays(GL_TRIANGLES, first, count)`
  - `first = 0, count = 3`: Evaluates vertices 0, 1, 2 using the current `ourColor` (Red).
  - `first = 3, count = 3`: Evaluates vertices 3, 4, 5 using the new `ourColor` (Green).

## 6. Common Traps & Pitfalls

1. **Setting Uniforms Before `glUseProgram`**:
   - Calling `glUniform*` before activating the shader program with `glUseProgram(shaderProgram)` is undefined or ignored on many OpenGL drivers. Always call `glUseProgram` first.
2. **Missing Commas in Float Arrays**:
   - Omitting commas between array elements (e.g., `0.0f \n -0.45f`) causes the C++ compiler to interpret it as subtraction (`0.0f - 0.45f`), reducing array size and corrupting vertex offsets.
3. **Invalid Uniform Location**:
   - If `glGetUniformLocation` returns `-1`, verify the variable name in the shader source exactly matches the string (case-sensitive) and that the uniform is actually actively referenced in shader logic (unused uniforms are optimized away by the GLSL compiler).
